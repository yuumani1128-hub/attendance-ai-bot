# 勤怠問い合わせAIボット

社内の勤怠ルールについて、自然言語で質問できる AI チャット Bot です。  
Streamlit で UI を提供し、OpenAI API と `rules.txt` を組み合わせて回答します。会話履歴を踏まえた追加質問や、文脈に沿ったルール説明に対応しています。

打刻漏れの修正可否や有給取得の最終判断など、管理者確認が必要な内容は LLM が確定せず、確認用テンプレートへ誘導します。

## 主な機能

- 会話形式で勤怠ルールについて質問できる
- セッション内の会話履歴を保持（上限 50 件）
- LLM による問い合わせ意図の理解
- 情報不足時の追加質問（例: 打刻漏れの出勤/退勤確認）
- 自然言語から `rules.txt` の関連セクションを検索
- 関連ルールと会話文脈に基づく LLM 回答
- 勤怠と無関係な問い合わせの除外
- 個別判断が必要なケースの管理者確認誘導
- サイドバーのよくある質問・おすすめ質問からの入力

## システム構成・処理フロー

固定的なカテゴリ分岐を主経路とする構成ではなく、LLM が意図と会話文脈を理解して処理します。キーワードによるカテゴリ判定は、ルール検索精度向上の補助情報として利用します。

```text
ユーザー
   │
   ▼
Streamlit UI（app.py）
   │
   ▼
会話履歴を取得（直近 10 件を処理に利用）
   │
   ▼
LLM による意図理解（llm.py / analyze_intent）
   │
   ├── 情報不足
   │      ↓
   │   追加質問（意図理解 API のみ、回答生成 API は呼ばない）
   │
   ├── 勤怠と無関係
   │      ↓
   │   対象外として案内
   │
   └── 勤怠に関する問い合わせ
          │
          ├── 個別判断が必要
          │      ↓
          │   管理者確認テンプレート
          │
          └── ルール確認
                 │
                 ▼
            rules.txt 検索（main.py / search_rules）
                 │
                 ▼
            関連ルールのみ取得
                 │
                 ▼
               LLM（generate_llm_response）
                 │
                 ▼
         文脈 + ルールに基づく回答
```

### ファイル構成

| ファイル | 役割 |
|---|---|
| `app.py` | Streamlit UI、会話履歴管理、表示整形 |
| `main.py` | 問い合わせ処理の本体（意図理解 → 分岐 → ルール検索 → 回答組み立て） |
| `llm.py` | OpenAI API 連携（意図理解・回答生成） |
| `rules.txt` | 社内勤怠ルールのデータソース |

```text
attendance-ai-bot/
├── app.py
├── main.py
├── llm.py
├── rules.txt
├── requirements.txt
├── .gitignore
├── images/
│   └── chat-ui.png
└── README.md
```

`.env` には OpenAI API キーを保存しますが、秘密情報のため Git 管理対象外です。

## LLM の役割

このアプリでは LLM が単なる文章生成だけでなく、次を担当します。

- ユーザーの意図理解（`rule_check` / `leave` / `attendance_correction` など）
- 会話文脈の理解
- 情報不足の判定と追加質問文の生成
- 取得した勤怠ルールに基づく自然な回答

Structured Output（Pydantic モデル）で意図理解結果を受け取り、`main.py` が追加質問・ルール検索・管理者案内へ振り分けます。

一方で、LLM が勤怠の確定・承認・修正可否を独自に判断する設計ではありません。個別対応が必要なケースは管理者確認を案内し、ルールに根拠がない内容は推測して回答しません。

---

## rules.txt の役割

`rules.txt` は回答の根拠となる社内ルールを `[セクション名]` 形式で保持します。現在は次のセクションがあります。

- 遅刻 / 電車遅延 / 打刻漏れ / 記載ミス
- 有給 / 午前休・午後休 / 休日出勤

ルールの利用方法は次のとおりです。

- 毎回 `rules.txt` 全文をそのまま回答に使うわけではない
- 問い合わせ文と意図に関連するセクションだけをスコアリングで抽出する
- 関連性の低いルールは回答に利用しない
- 該当ルールが見つからない場合は推測せず、管理者確認を案内する

## セットアップ

### 1. リポジトリを取得

```bash
git clone https://github.com/yuumani1128-hub/attendance-ai-bot.git
cd attendance-ai-bot
```

### 2. 依存関係をインストール

```bash
pip install -r requirements.txt
```

### 3. 環境変数を設定

プロジェクト直下に `.env` を作成し、OpenAI API キーを設定します。

```text
OPENAI_API_KEY=your_api_key_here
```

> API キー本体は README や GitHub に含めないでください。

## 利用例

### 追加質問（打刻漏れ）

```text
ユーザー:
打刻を忘れました

AI:
出勤と退勤、どちらの打刻でしょうか？

ユーザー:
退勤です

AI:
（管理者確認用テンプレートを表示）
```

### ルール確認（有給）

```text
ユーザー:
有給は何日前までに申請できますか？

AI:
（rules.txt の有給セクションをもとに、申請期限を説明）
```

### 個別判断（LLM は承認しない）

```text
ユーザー:
退勤を18時にしても大丈夫ですか？

AI:
このケースは個別確認が必要です。管理者へ確認してください。
（確認前に整理すべき項目を表示）
```

## API 利用について

- ユーザー発言ごとに、原則として意図理解の API 呼び出しが 1 回行われます
- ルール確認回答を生成する場合は、回答生成の API 呼び出しが追加で 1 回行われます
- 追加質問・勤怠外案内・管理者確認誘導のみの場合は、回答生成 API は呼び出しません
- `rules.txt` 全文ではなく、関連セクションのみを LLM に渡します
- 会話履歴は直近 10 件までを意図理解・回答生成の文脈として利用します
